# GelKaravan v2 — Правила работы с проектом

## Ветки
- `main` — всегда рабочий код, деплоится на new.gelkaravan.ru автоматически
- `feature/название` — каждая задача в отдельной ветке

## Workflow для каждой задачи

1. Создать ветку: `git checkout -b feature/название-задачи`
2. Субагент пишет код
3. Собрать: `npm run build` — должно пройти без ошибок
4. Сергей смотрит на new.gelkaravan.ru — одобряет или правит
5. Merge в main: `git checkout main && git merge feature/название && git push`

## Правила для субагентов

- Роль: senior разработчик + дизайнер в одном лице
- Всегда работать в feature-ветке, НЕ в main
- Перед началом: `git pull && git checkout -b feature/...`
- В конце: коммит + `npm run build` без ошибок
- Промпт показывается Сергею на подтверждение ДО запуска субагента

## Деплой

- `new.gelkaravan.ru` — staging (тестовый), main ветка
- `gelkaravan.ru` — production, только по явной команде Сергея "выкатываем"

## Бэкапы БД

## Правило подтверждения

1. Составляю промпт для субагента
2. Показываю Сергею — жду "всё ок, отправляй"
3. Только потом запускаю субагента

Без подтверждения — не запускаю. Никогда.
